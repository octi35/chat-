# ==========================================================================
# Plantilla de variables de entorno para ChatbotX (desarrollo local)
# ==========================================================================
# No pude leer chatbotx/.env.example directamente por el mismo guardrail
# de seguridad explicado en chatwoot-variables.txt (bloquea cualquier
# archivo .env* del proyecto, no configurable desde settings.json).
#
# Esta plantilla la arme leyendo:
#   - docker-compose.yml / docker-compose.dev.yml (servicios e infra)
#   - apps/builder/src/env.ts (validación de env con zod/t3-env)
#   - packages/database, packages/redis, packages/filesystem,
#     packages/encryption, packages/auth, packages/mail (cada uno valida
#     sus propias env vars con su propio keys.ts)
#   - packages/ai/src/core/factory.ts (proveedores de IA)
#
# INSTRUCCIONES:
#   1) Copiá este archivo a chatbotx/.env
#   2) Los valores marcados con <TU_...> son placeholders reales que tenés
#      que completar (ver docs/canales-pendientes.md y docs/ia-pendiente.md)
#   3) Los secretos ya vienen generados random para este entorno local
#      (ENCRYPTION_KEY, BETTER_AUTH_SECRET, JAVASCRIPT_EXECUTOR_TOKEN,
#      password de Postgres) — no los reutilices en producción.
#   4) docker-compose.yml ya trae defaults (`${VAR:-default}`) para varias
#      de estas, así que el stack levanta igual si algo queda vacío; los
#      valores de abajo son para que coincidan entre el compose y la app.
# ==========================================================================
